# 实验与证据

## 冻结基准

先识别实际执行入口、模型定义、权重、数据清单、类序、预处理、训练策略、检查点选择和推理策略。文件名相同、最佳轮次相同或测试分数相同，都不能证明两个运行相同。

每次运行用独立目录，保存配置、代码版本或摘要、种子、环境实测值、日志、历史曲线数据、检查点和逐样本预测。避免覆盖已完成结果。兼容版本表只能说明可安装组合，不能证明服务器实际装了该版本；本机环境也不能代表远端训练环境。

正式比较尽量保持划分、标签、输入、预训练、优化、预算、选模和推理口径一致。无法统一时逐项披露，称为“完整配置比较”，不将差异全部归因于单一模块。跨数据集或协议结果作为背景，不能直接排名证明优越性。

## 模块与消融

每个模块写清：观察到的问题、设计理由、实际插入位置、源方法与改动、输出形状、额外代价及验证方法。先检查最终模型真正包含哪些组件，再设计消融；不把后来新增的代码当成原模型组成。

两个组件可用以下因子表，按实际问题扩展：

| 配置 | 组件一 | 组件二 |
|---|---|---|
| 基础模型 | 关 | 关 |
| 单组件一 | 开 | 关 |
| 单组件二 | 关 | 开 |
| 完整配置 | 开 | 开 |

推理期策略复用对应已训练权重，避免暗中重训。对比相同条件下的差值；累计添加模块不自动隔离各模块贡献。组合最好可支持“在所评估配置中表现最好”；宣称稳定互补、机制或协同效应需要相应重复和交互分析。

重复次数、种子、均值和样本标准差以真实记录为准；单次最优、跨种子均值和事后集成分别报告。不得把历史最佳单次与另一批多次均值直接作组件因果比较。无需在每句话重复种子，但方法中交代口径，结论不超出证据。

测试集用于最终评价。若此前反复查看测试结果并据此选配置，应如实记录这种选择历史，不能凭一段新声明恢复独立测试地位。疑似错标由证据和独立复核处理；反事实改标签的敏感性分析不等于模型成绩提升。

## 轮数、早停与续训

分开记录最大轮数、实际停止轮数、最佳检查点轮数和最终评估轮数。训练结束评估的是哪一个权重，要从加载流程确认。

延长总轮数前检查学习率调度是否与总轮数绑定；改总轮数可能从早期就改变学习率轨迹。旧运行的前段与新运行的后段不能仅因数值接近而视为同一训练。

精确恢复需检查模型、优化器、调度器、混合精度缩放、随机数、采样器/数据顺序及必要的 EMA 状态和软件条件。只有模型权重时称为“从权重继续训练”，不得声称完整恢复。拼接历史曲线应保留来源、断点和状态差异；不能复制、插值补造缺失轮次来展示未发生的训练。用户可选择不画断点线，但图注仍须准确说明来源。

云端启动前检查现有进程和日志，避免重复训练。区分“跳过完成任务”“从头重跑中断任务”“断点恢复”。代码注释或绘图修改应检查语法及训练逻辑是否改变；未实际运行 GPU 时明确说明。

## 指标复算

核对类序、集合、运行和矩阵轴含义；不要仅凭图片名判断测试/验证。矩阵总数、各行真实类别支持数与清单一致后再计算。截图模糊时优先读取 CSV/JSON 或逐样本预测，不猜数字。

单标签分类中，行是真值、列是预测时：

- Accuracy = 对角线之和 / 总数。
- 类别 precision = 对角线值 / 该列总和；recall = 对角线值 / 该行总和。
- 每类 F1 = 2PR/(P+R)；macro-F1 = 各类 F1 的不加权平均。
- Balanced accuracy 通常为各真实类别 recall 的平均；核对库对缺失类和零分母的处理。

统一用 0–1 计算，展示时转换百分数；核对加权、宏平均和 micro 口径。准确率的整数正确数检查只适用于固定样本数的单次评估，不套用于折均值或多次均值。差异先查来源再改正文，不先猜相邻的“可实现”分数。

用未舍入数值计算、最后统一舍入。90% 到 92% 是增加 2 个百分点，相对增加约 2.22%；使用已舍入表值算差时明确口径。不以参数少推断速度快，不以热图证明因果或泛化。
